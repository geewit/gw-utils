# javafx-ui-guardrails

## 目的

为 JavaFX 页面、Dialog、表格、分页、表单、异步交互提供统一的 UI/UX 与状态管理约束，避免出现关闭事件缺失、搜索条件丢失、刷新后状态错乱、后台线程误更新 UI 等问题。

## 何时使用

当任务涉及以下内容时必须使用：

- JavaFX 页面开发或重构
- Dialog / Modal / Form
- TableView / Pagination / 搜索列表
- 批量勾选 / 批量操作
- 后台异步加载与 UI 回写
- 页面状态恢复与列表刷新

## 强制规则

### 1. Dialog

- 所有 Dialog 都必须实现统一的关闭事件处理
- 必须覆盖：
  - ESC
  - Cancel
  - 窗口关闭按钮
  - 右上角关闭
  - 提交成功自动关闭
- 若表单已修改未保存，关闭前必须确认
- 保存失败时不得关闭 Dialog
- 保存成功后应关闭 Dialog，并触发调用方明确刷新

### 2. 查询与分页

- 翻页不得丢失搜索条件
- 切换页大小默认保留搜索条件并回第一页
- 新搜索默认回第一页
- Reset 才允许清空条件
- 查询状态必须独立建模，不依赖当前页数据对象

### 3. JavaFX 线程纪律

- 不在 FX 线程做阻塞 IO
- 后台执行 -> FX 线程回写 UI
- 页面销毁后不得继续回写控件
- 提交中/加载中状态必须与异步生命周期一致

### 4. 刷新语义

必须明确区分：

- 当前页刷新
- 重新查询并回第一页
- 提交成功后的局部回填
- 关闭 Dialog 后的来源页刷新

不要默认每次都把页面全部重置。

### 5. 表单行为

- 输入校验、业务校验、服务端错误要区分
- 提交失败保留用户输入
- 二次打开 Dialog 不得残留上一轮脏状态

## 推荐状态模型

至少显式维护：

- `searchForm`
- `pageRequest`
- `pageResult`
- `loading`
- `submitting`
- `dialogDirty`
- `selectedIds`

## 输出要求

输出中必须说明：

1. 页面有哪些显式状态
2. Dialog 如何关闭与回调
3. 查询条件是否会跨刷新/翻页保留
4. 异步流程如何切换线程
5. 错误与空态如何反馈

## 禁止事项

- 禁止把页面状态混在单个 Controller 字段里随意修改
- 禁止翻页/刷新时丢失查询条件
- 禁止后台线程直接更新 UI
- 禁止保存失败自动关闭窗口
- 禁止没有 close handler 的 Dialog
