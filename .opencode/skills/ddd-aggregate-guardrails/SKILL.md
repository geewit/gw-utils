# Skill: DDD Aggregate Guardrails

## 适用场景

当任务涉及：
- 设计或审查聚合边界
- 将业务规则从 service/handler 搬回领域对象
- 判断一个对象是否应为实体、值对象、领域服务

## 强制规则

1. 先找不变量，再找聚合根。
2. 一个聚合默认只保证自身一致性，不要为查询方便塞入太多关系对象。
3. 聚合之间优先通过 ID 关联，而不是对象图深持有。
4. 如果一个方法只是编排，不属于聚合；如果一个方法维护业务不变量，应优先进入聚合根或领域对象。
5. 领域服务只处理无法自然归属到单个实体/值对象的规则。
6. 不要把数据库行模型直接当聚合。

## 检查清单

- 当前聚合根是谁
- 当前不变量是什么
- 当前是否过大
- 当前是否混入查询投影字段
- 当前是否泄漏持久化细节
