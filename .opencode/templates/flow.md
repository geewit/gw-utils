基于用户需求:

```markdown
   $ARGUMENTS
```

执行完整自动流程，但第一优先级不是直接实现，而是先盘点当前项目状态。
必须严格按以下阶段执行：
   ## Phase 0：读取规则与设计基线
      ### 1. 读取项目根目录 AGENTS.md。
      ### 2. 扫描仓库真实代码结构、模块边界、Gradle 配置、测试入口、现有相关代码。
      ### 3. 如项目存在 OpenSpec 产物，检查 openspec/specs、openspec/changes、proposal、design、tasks 以及当前 change 状态。
   ## Phase 1：当前状态盘点（必须先完成）
      ### 1. 把相关设计章节映射到当前代码证据、测试证据、配置证据。
      ### 2. 对每个相关子能力标记状态：
         - 已实现
         - 部分实现
         - 已实现但与设计不一致
         - 未实现
         - 无法判断
      ### 3. 输出盘点结果，至少包含：
         - 设计章节 -> 代码位置映射
         - 已实现项清单
         - 部分实现项清单
         - 设计偏差项清单
         - 未实现项清单
         - 本次真正需要继续处理的任务清单
       ### 4. 对“已实现”项不要重复开发；对“部分实现”项只补缺口；对“与设计不一致”项先说明偏差，再决定修正还是兼容。

   ## Phase 2：设计对齐与任务收敛
      ### 1. 把 instructions 作为首要设计基线，不要脱离该文档自由发挥。
      ### 2. 若项目已有 OpenSpec 结构，则优先把本次任务沉淀到 proposal / spec / design / tasks，并与盘点结果一致。
      ### 3. 若文档与仓库现状冲突，以仓库真实状态为准做增量方案，但必须明确记录偏差点。
      ### 4. 拆分出本次真正要处理的最小任务集合。

   ## Phase 3：实现代码
      ### 1. 只实现本次盘点后确认仍需处理的任务。
      ### 2. 严格遵守 AGENTS.md 和设计文档。
      ### 3. 仅做任务范围内的增量改造，不做无关大重构。
      ### 4. 如果现有实现与设计文档不完全一致，优先采用兼容现状的最小修复方案，并明确说明原因。
   ## Phase 4：补测试
      ### 1. 针对本次新增或修改的行为补充或修正测试。
      ### 2. 优先覆盖：正常路径、一个边界路径、一个异常路径。
      ### 3. 若现有测试失败，必须区分：测试过时、实现有 bug、还是环境/时序问题。
      ### 4. 不要为了通过测试而弱化断言。
   ## Phase 5：跑测与调试
      ### 1. 先跑与本次改动最相关的最小测试集，再决定是否扩大到模块级或全量。
      ### 2. 执行构建、测试、检查命令时，必须遵守 AGENTS.md 中的环境与命令约束。
      ### 3. 禁止使用 ./gradlew，必须直接使用 gradle。
      ### 4. 若测试失败，必须分类判断：
          - 生产代码缺陷
          - 测试预期过时
          - 环境 / 构建问题
          - Reactive / 并发 / 时序问题
          - 初始化 / 配置 / 依赖问题
      ### 5. 反复执行：跑测 -> 定位 -> 修复 -> 复测，直到通过或明确阻塞项。
   ## Phase 6：最终输出最终必须输出结构化总结，至少包含：
      ### 1. 当前任务归属的上下文
      ### 2. 本次参考的设计文档章节
      ### 3. 设计章节与代码实现映射
      ### 4. 设计文档与仓库现状的关键差异
      ### 5. 本次实际采用的实现策略
      ### 6. 修改文件清单
      ### 7. 新增或修改的测试文件
      ### 8. 验证命令
      ### 9. 验证结果
      ### 10. 剩余风险与后续可继续收敛点
      ### 额外要求：
         - 输出默认使用中文。
         - 代码、命令、日志、错误信息保持原文。
         - 除非真正阻塞，不要把中间不确定性抛回给用户；优先做最小合理假设并明确记录。
         - 不允许跳过 Phase 1 的当前状态盘点就直接进入开发。"
